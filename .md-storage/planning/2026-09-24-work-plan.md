## 2. Project Structure Overview

### 2.1 High-Level Architecture

```
alloy/
├── app/                          # Main application shell
├── core/                         # Shared core libraries
│   ├── common/                   # DI, events, registry, logging
│   ├── design/                   # Material 3 theme, desktop UX primitives
│   ├── datastore/                # Room + DataStore + SQLCipher
│   ├── proc/                     # /proc system telemetry readers
│   └── netlocal/                 # Ktor loopback server (Model Manager)
├── modules/                      # Phase 1 feature modules
│   ├── statspill/                # System telemetry widget & overlay
│   ├── scenes/                   # Workspace scene launcher
│   ├── clip/                     # Encrypted clipboard history
│   └── scratch/                  # Multi-instance pinned scratchpad
└── tooling/                      # Development utilities
    └── probe/                    # Platform validation utilities
```

### 2.2 Module Details

#### **app** - Main Application Shell
- **Purpose:** Primary application entry point, navigation, dashboard, settings
- **Dependencies:** All core and module libraries
- **Build Type:** Android Application

#### **core/\*** - Shared Libraries

| Module | Purpose | Key Features |
|--------|---------|--------------|
| `core:common` | Foundation utilities | DI setup, event bus, service registry, logging |
| `core:design` | UI components | Material 3 theme, desktop adaptivity, shared composables |
| `core:datastore` | Data persistence | Room database, DataStore preferences, SQLCipher encryption |
| `core:proc` | System telemetry | /proc filesystem readers for CPU, memory, network stats |
| `core:netlocal` | Local networking | Ktor loopback HTTP server for inter-process communication |

#### **modules/\*** - Feature Modules (Phase 1)

| Module | Purpose | Key Features |
|--------|---------|--------------|
| `modules:statspill` | System monitoring | Live CPU/RAM/battery/net telemetry, floating overlay |
| `modules:scenes` | Workspace management | Scene launcher with window bounds, hotkey support |
| `modules:clip` | Clipboard utility | Encrypted history, OCR, text transformations |
| `modules:scratch` | Note-taking | Multi-instance windows, checklists, stopwatch/timer |

#### **tooling/\*** - Development Tools

| Module | Purpose |
|--------|---------|
| `tooling:probe` | Platform validation and testing utilities |

## 4. Agent Workflow

### 4.1 Subagent Types Available

| Agent | Purpose | When to Use |
|-------|---------|-------------|
| **debugger** | Analyze stack traces, Gradle sync issues, Logcat crashes | Build failures, runtime exceptions |
| **explore** | Quick codebase exploration, file searches, pattern matching | Finding files, understanding code structure |
| **general** | Multi-step tasks, complex implementations | Feature development, refactoring |
| **planner** | Break down specs, track progress | Large features, multi-phase work |
| **reviewer** | PR audits, Compose recomposition, memory leaks | Code review, performance optimization |

### 4.2 Recommended Workflow

1. **For Build Issues:** Use `debugger` agent for Gradle/compile errors
2. **For Code Discovery:** Use `explore` agent with appropriate thoroughness level
3. **For Feature Implementation:** Use `general` agent for parallel task execution
4. **For Complex Specs:** Use `planner` to break down requirements
5. **For Code Quality:** Use `reviewer` before merging changes

### 4.3 Session Management

- Each subagent conversation has a unique `sessionID`
- Pass `sessionID` to continue specific conversations
- Use `background=true` for asynchronous work that doesn't block main flow
